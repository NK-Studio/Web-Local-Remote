Web Local Remote 사용법

Unity WebGL 빌드를 로컬에서 띄우고, Android와 iPhone에서 바로 열어 디버그하는 도구입니다.

개요

로컬 서버

Unity에 든 Node.js로 빌드 폴더를 바로 서비스합니다. 압축 빌드, 멀티스레드(COOP/COEP), 영상 Range 요청을 처리합니다.

폰 접속 QR

같은 와이파이의 폰으로 QR을 찍으면 빌드가 열립니다.

신뢰되는 HTTPS

로컬 루트 CA를 폰에 한 번 설치하면 iPhone에서도 경고 없이 카메라·서비스 워커·Brotli가 동작합니다.

원격 콘솔

폰의 로그와 오류를 PC 대시보드와 Unity 콘솔에서 실시간으로 보고, 폰에서 JS를 실행합니다.

요구 사항: Unity 6000.2 이상, WebGL Build Support 모듈, Windows 또는 macOS. 인증서 생성에는 OpenSSL(Git for Windows 또는 macOS 기본/Homebrew)이 필요합니다.

빠른 시작

  1. 창 열기 — 메뉴 Tools › Web Local Remote.
  2. 인증서 만들기 (처음 한 번) — 설정 탭 › 로컬 CA + 인증서 생성. 프로젝트의 .cert/에 루트 CA와 서버 인증서가 생깁니다. .gitignore 추가를 물으면 예를 고르세요.
  3. 빌드 폴더 고르기 — 서버 탭의 Browse로 WebGL 빌드 폴더(index.html이 있는 곳)를 지정합니다.
  4. 서버 실행 — ▶ Run. 상태가 Server Running이 되고 QR이 나타납니다.
  5. 폰에 루트 CA 설치 (기기당 한 번) — QR 위의 기기 설정 · 인증서를 누르고 폰으로 스캔해 안내대로 설치합니다. 자세히
  6. 빌드 열기 — QR을 빌드 열기로 돌려 스캔합니다. 폰의 로그는 원격 디버그 탭의 원격 콘솔 열기와 Unity 콘솔에 나타납니다.
폰과 PC가 같은 네트워크에 있어야 합니다. 회사·카페 와이파이처럼 기기 간 통신을 막는 곳에서는 Android USB 연결을 쓰세요.

HTTPS · 인증서

폰 브라우저는 보안 컨텍스트(HTTPS)에서만 카메라, 서비스 워커, Brotli 압축 응답을 허용합니다. 이 도구는 PC에 로컬 루트 CA를 만들고, 그 CA로 서버 인증서를 서명합니다. 폰에 루트 CA를 한 번 설치하면 이후 서버 인증서가 바뀌어도(와이파이 IP 변경 등) 다시 설치할 필요가 없습니다.

파일설명
.cert/rootCA.crt폰과 PC에 설치하는 루트 CA (10년)
.cert/rootCA.key루트 CA 개인 키. 절대 공유하거나 커밋하지 마세요.
.cert/server.crt / .key서버 인증서 (397일). localhost, 호스트.local, 현재 LAN IP가 들어 있고, IP가 바뀌면 서버를 켤 때 자동으로 다시 발급합니다.

폰에 루트 CA 설치

창에서 QR을 기기 설정 · 인증서로 바꿔 스캔하면 기기에 맞는 안내가 나옵니다. 처음 열 때는 아직 CA가 없으니 주소창에 경고가 뜹니다. 세부사항 › 이 웹 사이트 방문(iPhone) 또는 고급 › 계속(Android)으로 넘어가세요.

  1. Safari로 설정 페이지를 열고 인증서 받기 › 허용.
  2. 설정 앱 › 프로파일이 다운로드됨(또는 일반 › VPN 및 기기 관리)에서 설치.
  3. 설정 › 일반 › 정보 › 인증서 신뢰 설정에서 Web Local Remote CA를 켭니다. 이 단계를 빠뜨리면 계속 경고가 뜹니다.
  1. 설정 페이지에서 인증서 받기로 파일을 받습니다.
  2. 설정 › 보안 › 암호화 및 사용자 인증 정보 › 인증서 설치 › CA 인증서에서 받은 파일을 고릅니다. 기종마다 메뉴 이름이 달라서, 설정 검색창에 CA 인증서를 입력하면 빠릅니다.
  3. Chrome을 완전히 닫았다가 다시 엽니다.

PC 브라우저에서 경고 없애기

설정 탭 › 이 PC에서 CA 신뢰를 누르면 macOS 키체인(로그인) 또는 Windows 사용자 인증서 저장소에 루트 CA를 등록합니다. OS가 암호나 확인을 묻습니다. 등록 후 브라우저를 다시 열면 https://localhost:포트/__wlr/ 대시보드가 경고 없이 열립니다.

루트 CA를 신뢰한 기기는 그 CA로 서명한 모든 인증서를 믿습니다. rootCA.key가 밖으로 나가지 않게 하고, 테스트가 끝난 기기에서는 설정에서 프로파일/인증서를 지워도 됩니다.

원격 콘솔

서버는 빌드의 index.html을 보낼 때 <head> 바로 뒤에 작은 스크립트(/__wlr/client.js)를 넣습니다. 빌드 파일은 바뀌지 않습니다. 이 스크립트가 폰의 다음 정보를 PC로 보냅니다.

  • console.log / info / warn / error / debug — Unity의 Debug.Log도 여기로 나옵니다.
  • 잡히지 않은 예외, 처리되지 않은 Promise 거부, 리소스 로드 실패
  • 기기 정보: 화면·창 크기, 보안 컨텍스트, 교차 출처 격리(crossOriginIsolated), WebGPU 지원, User-Agent
  • 페이지가 백그라운드로 가거나 돌아올 때([page] hidden / visible)

Android와 iPhone 모두 같은 방식이라 USB 케이블이나 개발자 설정이 필요 없습니다.

Unity 콘솔

Unity 콘솔로 받기가 켜져 있으면 폰 로그가 [iPhone ab12] 메시지 형식으로 Unity 콘솔에 나옵니다. error는 Error, warn은 Warning으로 표시됩니다. 처음 연결할 때는 쌓여 있던 로그 중 최근 200개만 가져옵니다.

Play 모드에서 Error Pause를 켜 두었다면 폰의 오류 로그에도 에디터가 멈출 수 있습니다. 그럴 때는 이 옵션을 잠시 끄세요.

USB 개발자 도구

로그만으로 부족할 때(브레이크포인트, 네트워크, 성능, 메모리) 브라우저의 원래 개발자 도구를 씁니다.

  1. iPhone: 설정 › Safari › 고급 › 웹 속성 보기를 켭니다.
  2. Mac Safari: 설정 › 고급 › 웹 개발자용 기능 보기를 켭니다.
  3. iPhone을 USB로 연결하고, iPhone Safari에서 빌드를 엽니다.
  4. 원격 디버그 탭의 Safari 웹 속성 보기를 누르거나 Mac Safari 메뉴 개발자 › [iPhone 이름] › 페이지를 고릅니다.

Windows에서는 Apple이 iPhone 웹 검사를 지원하지 않습니다. 원격 콘솔을 쓰세요.

  1. 폰의 개발자 옵션 › USB 디버깅을 켜고 USB로 연결합니다. 폰에 뜨는 허용 창에서 허용.
  2. 원격 디버그 탭의 폰에서 열기를 누르면 연결된 모든 기기에 아래 명령을 실행하고, 폰 브라우저에서 https://localhost:포트/를 엽니다. 
    adb reverse tcp:8080 tcp:8080
    폰에서는 localhost로 접속하므로 와이파이가 막혀 있어도 됩니다.
  3. Chrome DevTools를 누르고 PC Chrome의 chrome://inspect/#devices에서 페이지의 inspect를 누릅니다.

adb는 Unity Android 모듈의 SDK, ANDROID_HOME, Android Studio SDK, PATH 순으로 찾습니다.

문제 해결

폰에서 "연결이 비공개로 설정되어 있지 않습니다" 경고가 계속 뜸
  • 루트 CA를 설치했는지, iPhone이라면 인증서 신뢰 설정까지 켰는지 확인하세요.
  • 설정 탭에서 인증서를 다시 생성했다면 루트 CA도 새로 만들어진 경우가 있습니다(이전 .cert/rootCA.*를 지운 경우). 폰에 다시 설치하세요.
  • 설정 탭의 CERT/KEY가 .cert/server.crt, .cert/server.key를 가리키는지 확인하세요. 다른 인증서를 쓰면 자동 재발급과 CA 안내가 동작하지 않습니다.
원격 콘솔이 비어 있거나 Unity 콘솔에 로그가 안 들어옴
  • 다른 프로그램이 같은 포트를 127.0.0.1에서 쓰고 있으면 PC 쪽 요청(대시보드, Unity 콘솔)이 그 프로그램으로 갑니다. 설정 탭에서 포트를 바꾸세요. 설정 탭의 인증서 상태에서 현재 주소를 확인할 수 있습니다. 예: macOS에서 다른 도구가 8080을 쓰는 경우.
  • 대시보드 왼쪽에 기기가 보이지 않으면 폰이 빌드 페이지를 이 서버에서 열었는지 확인하세요(다른 서버로 연 빌드에는 스크립트가 들어가지 않습니다).
QR로 접속이 안 됨 (시간 초과)
  • 폰과 PC가 같은 네트워크인지, PC 방화벽이 Node.js의 수신을 막지 않는지 확인하세요. macOS에서 처음 실행할 때 뜨는 "들어오는 연결 허용" 창에서 허용해야 합니다.
  • QR 주소는 기본 게이트웨이가 있는 네트워크의 IP입니다. VPN을 켜고 있다면 끄고 서버를 다시 실행해 보세요.
  • 기기 간 통신을 막는 네트워크라면 Android는 원격 디버그 탭의 폰에서 열기(USB)를 쓰세요.
카메라 권한 요청이 안 뜨거나 거부됨

HTTP로 접속하면 카메라를 쓸 수 없습니다. 주소가 https://인지, 주소창에 경고가 없는지 확인하세요. 설정 페이지 맨 위에 보안 컨텍스트와 교차 출처 격리가 모두 "예"로 나와야 합니다.

iPhone에서 영상이 재생되지 않음

iOS Safari는 영상 파일에 Range 요청(206 응답)을 요구합니다. 이 서버는 Range를 지원하므로, 다른 서버로 서비스할 때만 문제가 됩니다.

인증서 생성 실패

Windows는 Git for Windows(OpenSSL 포함)를 설치하세요. macOS는 기본 /usr/bin/openssl(LibreSSL) 또는 Homebrew OpenSSL을 씁니다.

서버 동작

  • 모든 응답에 Cross-Origin-Opener-Policy: same-origin, Cross-Origin-Embedder-Policy: require-corp를 붙여 멀티스레드 빌드가 동작합니다.
  • .br/.gz 파일은 브라우저가 그 인코딩을 받으면(HTTPS) Content-Encoding으로 그대로, 아니면 서버에서 풀어 보냅니다.
  • 캐시를 끕니다(Cache-Control: no-store). 빌드를 다시 하면 새로 고침만 하면 됩니다.
  • 로그는 서버 메모리에 최근 5,000개만 둡니다. 서버를 끄면 사라집니다.
